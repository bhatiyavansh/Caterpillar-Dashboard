# Person C — Data, Sensing & ML

Everything in this document is live and tested. If a number on your screen comes
from a machine, a worker, a task, a risk score or a prediction, it comes from here.

## Quick start

```bash
uv sync --extra dev
uv run python -m simulator --mode standalone
```

That gives you, on port 8100:

- `ws://localhost:8100/ws/live` — the live stream (new clients get the current
  world immediately, so screens are never blank)
- `GET /state` — full world snapshot
- `GET /scenarios`, `POST /scenario/{name}` — the director
- `GET /health` — mode, tick count, connected clients, hub status

Nothing else needs to be running.

> **macOS note:** LightGBM needs OpenMP. If `import lightgbm` fails with
> `Library not loaded: @rpath/libomp.dylib`, run `brew install libomp`.

## The three message types

Every message on the socket is one of these, and all three are defined as
Pydantic models in [`simulator/schemas.py`](simulator/schemas.py). **Do not
change a field name without telling me** — A, B and D all build against them.

| `type` | Rate | What it is |
|---|---|---|
| `machine_state` | 1 Hz × 9 machines | pose, implement angles, fuel, cycles, temps, tip-over margin, bubble, task progress + ETA |
| `worker_state` | 1 Hz × 6 workers | ground crew positions (simulated UWB) |
| `event` | when triggered | safety, anomaly and advisory events (12 kinds) |

A live example of every single one is in [`fixtures/`](fixtures/) — see below.

## Director (Person D)

`GET /scenarios` returns everything you need to render the buttons. Firing one:

```bash
curl -X POST localhost:8100/scenario/unbuckle
curl -X POST localhost:8100/scenario/reset
```

| Scenario | What happens |
|---|---|
| `start_shift` | reset counters, engines on, tasks ordered |
| `rain` | weather → rain, visibility 300 m, ground wet → muddy over 60 s, tasks resequenced, risk recalculated |
| `unbuckle` / `buckle` | EXC001 belt off → escalates chime → voice → travel locked over 15 s, then clears |
| `worker_behind` | a worker is pinned 3 m behind EXC001 for 10 s |
| `fatigue` | EXC001 fatigue score → 0.85 |
| `dozer_reversing` | DOZ001 reverses onto a converging path with EXC001 |
| `heavy_lift` | 3,200 kg, boom low, 8° slope — tip-over margin drops below 1.2 |
| `hydraulic_spike` | hydraulic temp +25 °C over 20 s |
| `idle_anomaly` | EXC002 idles 50 min with almost no cycles |
| `loader_queue` | 3 trucks queue at the loader |
| `reset` | everything back to normal |

**Scripted first, real later.** Each scenario can emit its event directly *and*
change the world so the real detector fires. Six have already been switched over
to the real detector (`EMIT_SCRIPTED_EVENTS` in
[`simulator/scenarios.py`](simulator/scenarios.py)) — `unbuckle`, `buckle`,
`worker_behind`, `fatigue`, `dozer_reversing` and `heavy_lift` now produce their
events through the actual safety rules and V2V path extrapolation. The scripted
path stays behind the flag as the on-stage fallback.

## For Person B

```python
from intelligence import (
    predict_task_time, predict_remaining,       # LightGBM quantile + SHAP
    get_anomalies, score_live_window,           # rules + Isolation Forest
    get_working_risk,                           # rules
    get_maintenance_forecast,                   # health extrapolation
    run_what_if,                                # headless re-simulation
    fleet_kpis, owner_summary, utilization_series,
    leaderboard, training_profiles, incident_index, heatmap_points,
    get_machine_status, get_fleet_overview,     # thin HTTP to :8100
    get_shift_tasks, reorder_tasks, trigger_scenario,
)
```

Every one returns plain JSON-safe Python — no numpy types, no NaN, no datetimes
— and a test enforces it. Models load lazily, so importing the package is cheap
(~0.2 s) even before training has run. The `get_*` wrappers have a 2 s timeout
and return empty rather than raising, so your agent never hangs on a restarting
simulator.

**C detects and predicts; you explain.** Nothing in `intelligence/` writes
prose — `reasons` and `evidence` give your LLM what it needs to write the
sentence.

For `/api/director/{scenario}`, proxy to `POST localhost:8100/scenario/{name}`.
To receive the stream, run the simulator in hub mode:

```bash
uv run python -m simulator --mode hub --hub ws://localhost:8000/ws/ingest
```

It reconnects with backoff, queues while you are down, and keeps serving
`/ws/live` and `/state` throughout — so restarting your backend never takes the
demo down.

## For Person A

- `pos.x` / `pos.y` are metres, x east, y north, site is 400 × 300. `lat`/`lon`
  are derived (origin 13.0827, 80.2707 — Chennai).
- `heading_deg`: 0 = north, clockwise.
- `bubble` is `green` / `amber` / `red`, already computed — radii scale with
  speed, and an excavator mid-slew adds its swing envelope.
- `v2v_collision_risk` events carry `path_a` and `path_b`: 11 predicted points
  at 0.5 s intervals, ready to draw as dashed lines.
- The haul road is a **one-way loop** — trucks run loader → dump on the north
  lane and return on the south lane. `site_layout.json` has the road polyline.
- `data/incident_tracks/*.json` — 4 incidents with full 60-second frame-by-frame
  tracks for replay.
- `data/runs/expert_run.json` and `novice_run.json` — the same trenching task
  done twice, 180 frames each, for the ghost challenge.

## Models

```bash
uv run python data-gen/generate.py --days 30 --seed 42   # ~180k rows
uv run python -m intelligence.train                      # ~8 seconds
```

Numbers for the pitch slide, all measured on a held-out 20% split:

| | |
|---|---|
| Task-time P50 MAPE | **9.7%** |
| The site planner's own estimate, same rows | 27.6% |
| P10–P90 interval coverage | **79.6%** (target 80%) |
| Injected anomaly shifts recovered | **8 / 10** |
| Brief's sample rows flagged | **2 of 2**, zero false alarms |

That last row is the one to say out loud: the four rows in the challenge brief
are expanded into per-minute telemetry inside our own history that aggregates
back to exactly the given fuel, cycles and idle minutes — and the model flags
precisely the two marked "Safety Alert Triggered = Yes", identifying both
co-occurring patterns (`excessive_idling` + `seatbelt_violation`).

## Things worth knowing

- **Everything is seeded.** Same seed → same data, same simulation.
- **Values are coupled, not random.** Cycles drive task progress; work drives
  fuel burn and hydraulic temperature; idling burns fuel while producing
  nothing. That is what makes the idle-anomaly story land.
- **Workers keep clear of machines** unless something goes wrong, so near-misses
  are rare and mean something (~6 per simulated hour, ~170 events per 10 h shift
  across the whole fleet).
- **Task ETA and progress agree by construction** — both come from the same
  production-rate formula as the historical ground truth.

## Known limitations

- `run_what_if` steps at 2 s rather than 1 s for speed (~25 s for the
  comparison). Throughput, fuel, idle and risk are solid; its `near_misses`
  count is approximate at that step size.
- `EXC003` is a spare machine that exists in the historical data only — it is
  what makes the fleet "9 active of 10". It is not in the live simulation.
- The webcam distance heuristic is uncalibrated (see
  [`web/components/cv/README.md`](web/components/cv/README.md)).
